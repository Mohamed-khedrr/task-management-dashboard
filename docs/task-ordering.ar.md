# ترتيب المهام بالسحب والإفلات

## الفكرة باختصار

كل مهمة لها رقم اسمه `order`، والعمود يعرض المهام من الرقم الأصغر إلى الأكبر.
عندما تسحب بطاقة وتفلتها، نعطيها رقمًا جديدًا يقع **بين** رقم البطاقة التي فوقها ورقم البطاقة التي تحتها.
بهذا تتغير بطاقة واحدة فقط، فنرسل **طلبًا واحدًا** فقط إلى الخادم، باستخدام json-server كما هو بدون أي إضافات.

## لماذا لا تكفي مكتبة CDK وحدها؟

مكتبة `@angular/cdk/drag-drop` تحرّك البطاقة على الشاشة أثناء السحب، وعند الإفلات تخبرنا فقط بمكان الإفلات (`currentIndex`) وبالعمود الجديد.
لكنها **لا تغيّر بياناتنا ولا تحفظ شيئًا** في الخادم. لذلك نحفظ مكان البطاقة بأنفسنا في الحقل `order`، حتى يبقى الترتيب بعد إعادة تحميل الصفحة.

## كيف نحسب الرقم الجديد؟

الدالة `getOrderAt` في الملف `src/app/core/utils/task.utils.ts` تنظر إلى البطاقة التي **فوق** مكان الإفلات والبطاقة التي **تحته**:

| مكان الإفلات                | الرقم الجديد | السبب                        |
| --------------------------- | ------------ | ---------------------------- |
| بين بطاقتين رقماهما 10 و 20 | 15           | منتصف المسافة بينهما         |
| في الأعلى، فوق البطاقة 10   | 9            | أصغر من أول بطاقة بواحد      |
| في الأسفل، تحت البطاقة 20   | 21           | أكبر من آخر بطاقة بواحد      |
| في عمود فارغ                | 0            | لا توجد بطاقات، فأي رقم يصلح |

```ts
export function getOrderAt(columnTasks: Task[], index: number) {
  const above = columnTasks[index - 1]; // البطاقة التي فوق مكان الإفلات
  const below = columnTasks[index]; // البطاقة التي تحته

  if (!above && !below) {
    return 0; // عمود فارغ
  }
  if (!above) {
    return getTaskOrder(below) - 1; // أُفلتت في الأعلى
  }
  if (!below) {
    return getTaskOrder(above) + 1; // أُفلتت في الأسفل
  }
  return (getTaskOrder(above) + getTaskOrder(below)) / 2; // بين بطاقتين
}
```

ملاحظة: نمرّر إلى الدالة بطاقات العمود **بدون** البطاقة المسحوبة، حتى لا تُحسب جارةً لنفسها.

## مثال كامل

عمود فيه ثلاث بطاقات:

| البطاقة | `order` |
| ------- | ------- |
| أ       | 10      |
| ب       | 20      |
| ج       | 30      |

نسحب **ج** ونفلتها بين **أ** و **ب**:

- البطاقة فوقها: **أ** (10)
- البطاقة تحتها: **ب** (20)
- الرقم الجديد لـ **ج** = (10 + 20) ÷ 2 = **15**

النتيجة: أ (10)، ج (15)، ب (20). الرقمان 10 و 20 لم يتغيرا، فنرسل طلب `PUT` واحدًا للمهمة **ج** فقط.

## المهام التي لم تُسحب أبدًا

بيانات الـ API لا تحتوي على الحقل `order`. لذلك الدالة `getTaskOrder` تستخدم وقت إنشاء المهمة (`createdAt`) بدلًا منه:

```ts
export function getTaskOrder(task: Task) {
  return task.order ?? Date.parse(task.createdAt);
}
```

النتيجة: المهام القديمة تظهر أولًا، والمهمة الجديدة تظهر في أسفل عمودها.

## حفظ الإفلات

الدالة `moveTask` في `TaskService`:

```ts
moveTask(move: TaskMove) {
  const task = this.tasks.value().find((t) => t.id === move.taskId);
  if (!task) {
    return;
  }

  let movedTask: Task;
  if (task.status === move.status) {
    // في العمود نفسه: نغيّر الرقم فقط، دون تغيير updatedAt
    movedTask = { ...task, order: move.order };
  } else {
    // إلى عمود آخر: نغيّر الحالة وتاريخ الإنجاز ومعهما الرقم
    movedTask = { ...this.applyChanges(task, { status: move.status }), order: move.order };
  }
  this.replaceTask(movedTask); // نحدّث اللوحة فورًا

  this.http
    .put<Task>(`${this.url}/${task.id}`, movedTask, { context: withRetry() })
    .subscribe({ error: () => this.replaceTask(task) }); // إذا فشل الحفظ نُرجع المهمة كما كانت
}
```

هذا ما يسمى **التحديث المتفائل** (optimistic update): اللوحة تتغيّر قبل أن يردّ الخادم، فلا ترجع البطاقة إلى مكانها أثناء الانتظار. وإذا رفض الخادم الطلب، نُرجع المهمة إلى حالتها السابقة.

## رحلة الإفلات خطوة بخطوة

1. **`TaskColumnComponent.onDrop`**: إذا أُفلتت البطاقة في مكانها نفسه لا نفعل شيئًا. غير ذلك نحسب الرقم الجديد بـ `getOrderAt` ونرسل الحدث `taskMoved` ومعه `taskId` و `status` و `order`.
2. **`TaskBoardComponent.moveTask`**: يمرّر الحركة إلى الخدمة.
3. **`TaskService.moveTask`**: يحدّث اللوحة فورًا، ثم يرسل طلب `PUT` واحدًا إلى `/tasks/:id`.
4. **`groupByStatus`**: يقسّم المهام إلى الأعمدة ويرتّب كل عمود حسب `getTaskOrder`، فتظهر البطاقة في مكانها الجديد.

## لماذا اخترنا هذه الطريقة؟

- **طلب واحد لكل إفلات**، مهما كان طول العمود.
- تعمل مع json-server كما هو، كما يطلب التكليف، بدون خادم أو مسارات إضافية.
- الطريقة الأخرى (ترقيم العمود كله 0، 1، 2، ...) كانت ترسل طلبًا لكل مهمة تغيّر رقمها، لأن json-server لا يدعم التحديث الجماعي.

## حدود هذه الطريقة

- بعد عدد كبير جدًا من الإفلات في المكان نفسه بالضبط، تقترب الأرقام من بعضها كثيرًا. هذا لا يحدث في الاستخدام العادي، وفي نظام حقيقي يعيد الخادم ترقيم العمود من وقت لآخر.
- تغيير الحالة من نافذة التعديل يُبقي رقم `order` القديم، فتظهر المهمة في العمود الجديد حسب ذلك الرقم، وليس بالضرورة في أعلاه أو أسفله.
- عند تفعيل فلتر، نحسب الرقم من البطاقات الظاهرة فقط.
